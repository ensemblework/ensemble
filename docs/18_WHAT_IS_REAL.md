## Starting it

```bash
pnpm infra:up
pnpm db:migrate
pnpm dev
```

`pnpm infra:up` starts Postgres and Redis. `pnpm db:migrate` applies migrations and does not reset the database. `pnpm dev` starts the API on port 4000, the site on port 3000, and the agent on port 5055.

`pnpm dev` now starts the model runtime too. `scripts/agent-dev.sh` creates `apps/agent-runtime/.venv` on first run with any Python ≥ 3.11 it can find (the macOS system Python 3.9 is too old).

Open http://localhost:3000. You are sent to **/login**. In development, the first account claims localhost placeholder data and lands on **/start**. Hosted public registration never claims placeholder data.

`ENSEMBLE_DEV_AUTH_BYPASS=true` still gives the old no-login mode for scripts.

## Real today

### Accounts and sign-in
- Sign-up, sign-in, sign-out, profile editing, and password changes (Settings → Account). Passwords are scrypt-hashed; sessions are an httpOnly cookie whose SHA-256 is the only thing stored. A new password needs 8 characters not counting spaces at the start or end, so one of only spaces is refused, on the server and in the forms; sign-in keeps the older rule so older accounts can still get in ([02 §16](02_MODULE_INTERACTION_HUB_UI.md#16-accounts-and-public-signup)).
- Public signup remains open after the first account. `ENSEMBLE_SIGNUP_MODE` provides `open`, `allowlist` and `closed`. Google/GitHub/Microsoft identity login, 4-character email verification codes, password reset, linked login methods, account export and deletion are implemented in `routes/auth.ts` and `routes/auth-oauth.ts`; see [02 §16](02_MODULE_INTERACTION_HUB_UI.md#16-accounts-and-public-signup). Provider buttons require separate configured `AUTH_*` clients; email requires Resend and Turnstile. Microsoft email ownership is verified by Ensemble, not assumed from an email/username claim. Existing private password accounts are grandfathered as verified by the public-signup migration; existing onboarded accounts are grandfathered as profile-complete by the profile migration.
- Landing `/privacy` and `/terms` are starter policy pages, not a claim of legal review. Registration links no longer describe an invitation requirement; GitHub links are enabled for the now-public repository.
- Every API route requires a session, a personal token (`Authorization: Bearer ens_…`), or the internal token agent-runtime uses. CORS only answers the Hub's own origin.
- The live event stream uses a one-use ticket, because it connects to `127.0.0.1` and the cookie belongs to `localhost`.

### Models
- The model runtime (`apps/agent-runtime`) is the only process that holds model keys (docs/11 §5). hub-api always names the provider with the model: the tier's, or the one the model picker sent, or the tier that lists that model; a model name alone is refused with a message, never routed by a guess (`providerForModel` in `lib/model-choice.ts`, `provider_for_call` in the runtime). The runtime resolves that provider's key and calls that vendor, and its errors name that provider.
- **Google Gemini**: live. Tested with `gemini-3.5-flash-lite` for chat with tool calls, plain completions, and JSON triage. It is the default on every tier because it is the cheapest; `gemini-2.5-flash-lite` is no longer offered to new keys. The request goes to Google's OpenAI-compatible endpoint with the key as a bearer token.
- **Cursor**: the key is validated and its models listed live (`api.cursor.com/v0/models`). Cursor runs agents, not a chat endpoint, so choosing it for the chat gives a clear error. It is meant for delegated runs (the next step).
- **OpenAI, OpenRouter, Ollama, Anthropic (native Messages API with tools), GitHub Copilot**: the adapters are written. They were not called live, because no keys for them were available.
- **GitHub Copilot** takes the person's own GitHub token and sends it as a bearer token to `https://api.githubcopilot.com` (`copilotEndpoint` in `apps/hub-api/src/runtime/models.ts`, `_copilot_endpoint` in `apps/agent-runtime/ensemble_agent/models.py`). The token must be a fine-grained token with the account permission **Copilot requests** (GitHub's documented way to make Copilot requests for a user); Settings → Models links to GitHub's form with that permission filled in. A classic `ghp_` token is refused before any call, and a token GitHub refuses gets a message that says which token to make. Until 13 Oct 2026 Ensemble exchanged the token at GitHub's internal `copilot_internal/v2/token` endpoint, which answers 404 for every token a person can make, so no Copilot key could be saved. Models Copilot serves only on `/responses` (gpt-5.4, gpt-5.4-mini, the codex models; the list's `supported_endpoints` says so) are sent there since 14 Oct 2026, and a refusal that names the other endpoint switches once and is remembered (`runtime/responses-api.ts`, `ensemble_agent/responses_api.py`). The model list offers chat models only. Checked with mocked HTTP only, not with a real Copilot account.
- **Settings → Assistant → Models → Manage API keys** (the *API keys* page, a dialog since 15 Oct 2026): paste a key per provider. It is checked against the provider before it is saved, then stored encrypted per account. A key you paste wins over the server's `.env` key. Hosted public accounts cannot borrow server env/CLI credentials or host Ollama; only verified exact `ENSEMBLE_OPERATOR_EMAILS` accounts can. Dev and desktop retain local fallback behavior. The model catalog is fetched live from each provider. The same dialog has a **Test** button per tier.
- The chat assistant uses the tier's provider. Verified: "add a todo…" produced a real `hub_create_tasks` call through Gemini, held for your approval because the write policy is "preview".

### Needs me: a real router for other agents' permission prompts
- A hook in **Cursor** (shell commands and MCP calls), **Claude Code** (every permission prompt), or **VS Code Copilot agent** (tool calls that change things) holds the tool call open and posts it to Ensemble. The card appears on Needs me live. **Allow once**, **Allow for this session**, **Always allow**, or **Deny** (with a reason) goes back to that exact call, in each tool's own output format.
- Verified end to end with the real hook script and each editor's payload shape. Cursor received `{"permission":"allow"}`; the same command in the same session was then allowed at once by the rule. Claude Code received a `PermissionRequest` deny with the reason. Copilot received a `PreToolUse` allow. Read-only tools (read_file and the like) never prompt.
- If Ensemble is down, or nobody answers within 10 minutes, the editor shows its own prompt. **The hook never allows on its own.**
- Setup: Settings → Connections → Editors & agents → *Answer permission prompts from Needs me* → Create token, then run the one install command shown for each editor. `scripts/ensemble-hook.mjs install|uninstall` writes `~/.cursor/hooks.json`, `~/.claude/settings.json`, or `.github/hooks/ensemble.json` and keeps any hooks already there.
- Standing answers ("always allow `npm test`") are listed and removable in Settings.
- **Not yet tested inside the real editors on this machine.** Restart the editor after installing, and check its Hooks panel or output channel if a prompt does not arrive.

### Code on this computer
- **Assign to agent** creates a `WorkspaceJob` (`routes/agents.ts`). `startAgentQueue` in `index.ts` starts the queue. `worker.ts` claims a queued job and calls `executeJob` in `agent.ts`, which prepares the folder, calls agent-runtime for each model turn, and runs the tools. A job that was running when the process died is marked interrupted on the next launch.
- The sandbox is macOS-only (`sandboxAvailable` in `guard.ts`). On Linux and Windows the same job can run as "This machine", with the argument allow-list and the path jail, and without Seatbelt.
- `unattended` is stored per job: a local code job keeps the assigner's choice (`workspace/assign.ts`), and a job sent to a paired device is always `false`. `orchestration.runWithoutAsking` lets commands in a trusted folder run without a prompt (`silentWorkspace` in `workspace/trust.ts`).
- Choosing Cursor as the model for a local task is refused. Cursor's cloud agents are a different path.

## Cowork surfaces (feature-one)

In-app, not email. Schema change is `20260929180000_cowork_surfaces`.

- **Morning brief**: Settings → Morning brief (default 08:00, on). Starting on the next local calendar day after signup, the scheduler writes one notification per day from the current Today context, using the Low model and the `morning-brief` personal skill. The first delivery opens a customization dialog when the user next has Ensemble open. `/morning-brief` reads the brief and edits/tests its skill; ordinary Skills editing also works. - **Meetings**: ambient cards on Today (not a modal), keyboard notes, confirmation before attaching notes onto the calendar event stored in Ensemble. Declining keeps them under Meeting notes, with the floating assistant available for cross-meeting questions. **Calendar sync is read-only**, so attach does not update Google or Outlook. Voice is a TODO; there is no microphone.
- **Workspace search**: one compact top-bar **Search and jump** dialog combines `/api/context/search` content matches with views, nested settings, actions and spaces. Cmd/Ctrl+K opens it; the sidebar Jump to entry is removed. Content matches retain excerpts, destination highlighting and early-Enter handling.
- **Weekly recap**: `/recap`, copy or download. Meeting rows are the per-meeting recap text. Slipped lists every open task past due (as of today, or the end of a past week), not only the ones due that week; a date from another year shows the year (`slippedLinks` in `cowork/recap.ts`).
- **Quiet nudges**: Settings → Quiet nudges, default 14 days. Keep, snooze (7 days), done, or Trash.
- **Shortcuts**: `packages/shared-types/src/shortcuts.ts` is the only binding list. The help sheet is `?`. Alt+Shift+T cycles starred code themes (not Ctrl+Alt+T).

## Code themes (feature-themes)

Code review and every plot code pane share a VS Code theme picker. Built-in themes live in `@ensemble/ide-theme`. Open VSX themes are fetched through hub-api (`/api/themes/search`, `/api/themes/openvsx`) and cached under `.theme-cache` (gitignored). The choice is `ideTheme` on the user settings document, so there is no database migration. Star up to three themes; Alt+Shift+T switches between them. The picker also imports compatible Marketplace VSIX packages and JSON/JSONC color files (no extension scripts run). Imported themes are cached on that browser/device, up to eight; their IDs/favorites sync but their files must be imported on another device. Plot code editing is disabled on narrow or short screens with a clear view-only message.

## OS sandbox on every system, one runtime for the CLI and the app, Claude Code as an engine (11 Oct 2026)

- **Sandbox on macOS, Linux and Windows, no Docker.** Every agent command goes through `startSandboxed` (`apps/hub-api/src/workspace/sandbox/spawn.ts`), which uses the computer's own sandbox: Seatbelt on macOS (unchanged), bubblewrap on Linux when the distribution has it and user namespaces work, else Landlock through the bundled `landrun` helper (built from pinned source by `scripts/build-landrun.mjs`), and on Windows a separate `srt-sandbox` account with folder grants and a network fence from Anthropic's sandbox-runtime (`@anthropic-ai/sandbox-runtime` 0.0.79). The backend is found once at start (`prepareSandbox`). A run that asks for the sandbox on a computer without one is refused with the reason and the fix; it never runs unconfined silently. Doc [24](24_DESKTOP_SANDBOXING.md) "Changes in v4".
- **Setup.** Nothing on macOS or Linux. Windows needs one admin prompt per computer: `ensemble sandbox setup`, Set up in the Assign dialog, or automatically at `ensemble login` on Windows. `GET /api/sandbox`, `POST /api/sandbox/setup` (on the computer only).
- **One runtime per computer.** The CLI now uses the desktop app's data folder (database, pairing, trusted folders, sandbox), moves an older CLI's data there once (`apps/cli/src/migrate.ts`), and a lock (`src/desktop/runtime-lock.ts`) keeps a second runtime from opening the same database. The app attaches to a CLI runner that is already running and takes over on the same port if it stops; `ensemble login` reuses the app's pairing. The default workspace is `~/ensemble-workspace` (it was `/tmp/ensemble-workspace`, cleared on reboot).
- **Paths outside the folder follow the sandbox.** Sandbox on: the **Outside the work folder** setting decides (Settings → Orchestration, or per run in the Assign dialog). Read only is the default: reads go ahead; a write asks in Ask and is refused back to the model in Review only and Run unattended, and the run continues. Read and write lets both go ahead; No access keeps the run in the folder. An allowed path is granted to the sandbox for that command, read-only unless it writes, and Claude Code's own sandbox gets the same paths. Sandbox off: Review only and Run unattended use them without asking. Keys, dotfiles in the home folder, Ensemble's data and code, and other accounts are refused in every mode (`outsideRefusal` in `workspace/guard.ts`).
- **Trusted folders are trusted in the person's other AI tools too** (on by default, per computer): Claude Code and the Claude app (`~/.claude.json`), Codex CLI and app (`~/.codex/config.toml`), GitHub Copilot CLI, Cursor's agent and Gemini CLI, so a folder is not trusted twice. Ensemble removes only the marks it added, keeps a copy of each file, and never rewrites a file it cannot read (`workspace/trust-share.ts`, doc 24 §5.8). Settings → Autonomy, or `ensemble trust share on|off`. The editors' own trust prompts (VS Code, Cursor) are not covered.
- **Claude Code as the engine.** Assign → "Who does the work" → Claude Code runs the person's own `claude` headless with their own sign-in (`workspace/engines/claude-code.ts`). A per-run PreToolUse hook sends every tool call to `/api/engine/ask`, judged by the run's mode, trust, outside-path, git and internet rules (`engines/judge.ts`); questions go through Ensemble's `ask_person` MCP tool (`scripts/ensemble-ask-mcp.mjs`) to Needs me. With the sandbox on, Claude Code's own sandbox confines its shell commands to the work folder, strictly. Doc [30](30_ENGINES.md).
- **Codex as the engine** (12 Oct 2026): Assign → "Who does the work" → Codex runs the person's own Codex through `codex app-server` (`workspace/engines/codex.ts`), the standalone CLI or the copy inside the ChatGPT app, with its own sign-in (refused with how to sign in when there is none). Codex keeps its own sandbox with the run's folders and internet; every approval it asks for is judged by the run's rules, its questions and `ask_person` reach Needs me, and the folder's own `.codex/` does not run. Checked against Codex 0.162 and end to end with a stand-in (`engines/codex.e2e.test.ts`). Doc [30](30_ENGINES.md) §2.
- **Cursor's agent as the engine** (12 Oct 2026): the person's own `cursor-agent` through ACP with its own login (`engines/cursor.ts`); every permission it asks for is judged by the run's rules and answered once (never "always", which would change the person's Cursor allowlist), and its questions reach Needs me. Doc 30 §3.
- **A task can open in the agent's own app, or a terminal** (12 Oct 2026): "In its own app or a terminal" opens the Claude app, Codex in the ChatGPT app, Cursor or VS Code on the folder with the task written in (the person presses Send; no vendor lets another app send), or starts Claude Code, Codex, Cursor's agent or Copilot CLI in a terminal window with the task as its first prompt. `ensemble hooks connect <tool>` connects a tool from the terminal. - **Only Ensemble's tasks reach Needs me from the tools' hooks, and Claude's can be answered in either place** (12 Oct 2026): a session Ensemble did not open is answered by the tool itself at once. Claude Code's questions now go through `PermissionRequest`, so Claude's own card stays open beside Needs me and the first answer counts; a card answered in the tool closes itself. Settings → Editors & agents → Connect installs the hook with a `hooks` key that can ask but never answer. Doc 30 §5.
- **Other tools' questions reach Needs me.** The hook (`scripts/ensemble-hook.mjs`) now covers Claude Code's multiple-choice questions (each option, its description, multi-select, a typed answer), Codex (`PermissionRequest`, approve the hook once in Codex's `/hooks`) and GitHub Copilot CLI (`~/.copilot/hooks`). `ensemble needs` lists and answers them too. The packaged app now ships the hook (it pointed at a missing file before).

## One-time Google setup (whoever runs this Ensemble)

Gmail and Calendar share one **Sign in with Google** button. People using Ensemble never open Google Cloud. The host does this once. It is separate from the Gemini key.

The console is now **Google Auth Platform** (not the old “OAuth consent screen” menu).

1. [Audience](https://console.cloud.google.com/auth/audience): External, publishing status Testing.
2. Branding: app name, support email = your Gmail. Save before adding test users. If Google says an address is ineligible, Branding or Data Access was not saved yet.
3. Data Access: add scopes `gmail.readonly`, `calendar.events`, `calendar.calendarlist.readonly` and `drive.file` (and `drive.readonly` only if you offer Search all of Drive). Enabling the APIs in the Library is not this step.
4. Clients → Web application. Redirect URI: `http://localhost:4000/api/connectors/google/callback`.
5. Paste the client ID and secret in **Settings → Connections → Google Workspace → Set up once** (shown to the operator only), or set `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` in `.env`. Without them the sign-in client (`AUTH_GOOGLE_CLIENT_ID` / `AUTH_GOOGLE_CLIENT_SECRET`) is used, so add the redirect URI above to that client.
6. Audience → Test users: add each Gmail that will press the button, including yours. While the app stays in Testing, Google blocks everyone else. Publishing Gmail access for the public needs Google’s own verification, which is a later step.

After that, each person presses **Connect** on Google Workspace and approves the products they switched on. Nobody else sees the secret.

GitHub sign-in works the same way with a GitHub OAuth App (callback `http://localhost:4000/api/connectors/github/callback`). A pasted fine-grained token needs no setup. Microsoft 365, Linear, Notion, Atlassian, Slack, Zoom and Docusign apps are set up the same way; the steps for each are in Settings → Connections → Browse connectors → the connector → Set up once (`GET /api/connectors/apps`).
