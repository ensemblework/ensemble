# Phone steering, end to end on a local stack (2026-11-22)

The owner steers an Ensemble Node from the Node website on a phone: sends work that runs on the paired computer, answers the node's cards with one press, receives screenshots and videos, and leaves the computer working with the phone's browser closed. Everything ran on this computer against `eval/node/serve.ts` (serve mode), never a hosted environment.

## Problems found

1. **Fixed (b1b34c84).** An app ask for the node's own agent screen said "@assistant wants to use Terminal on your screen on Eval computer". The computer now says which screen (`NodeToolAsk.screen`, `src/remote/contract.ts`; `appAsk` in `src/desktop/control/device.ts:35`), and the card says "on its own screen" (`title` in `src/node/device-tool-decisions.ts:145`) and carries `data.screen`. Tests failed first: `desktop.test.ts` (2) and `device-tools.integration.test.ts` (1). **Website, to route:** the answered card's line still says "Allowed @assistant to use Terminal on your screen · This mission": `apps/node-web/lib/cards.ts:139` (`kind === "app"`) words every app ask as the owner's screen; it should read `data.screen === "agent"` ("on its own screen"), with `lib/cards.test.ts:76` and `lib/checkpoints.test.ts:163-164`.
2. **Open (agent screen).** Apps that start by D-Bus (Settings, Terminal/Ptyxis) show no window the node can see on the agent screen: `desktop_open` answers after 10 to 20 s that the app started but shows no window, and the node gives up. The process runs on the agent screen's bus with its display (mutter sets the relative `WAYLAND_DISPLAY` through `UpdateActivationEnvironment`), but it never registers on the agent screen's AT-SPI bus (its registry lists only gnome-shell), and `apps_launch` finds windows through AT-SPI (`desktop-helper/linux/desktop_helper/server.py:868-919`, `_running_for`). Calculator, started directly from its `Exec`, works. Giving the private bus the display from the start did not change this (tried, dropped). Next to check: how an app started by the private bus finds the AT-SPI bus (`org.a11y.Bus` on that bus, `AT_SPI_BUS_ADDRESS`).
3. **Open (cost).** Sending a held capture always queues an `approval` turn (`src/node/approvals.ts:402-411`), also when the turn that made the capture is still running and shows it itself. In S1 the extra turn read 40k input tokens to answer "(no reply)", and the chat showed the node working again after its reply (30k in the rerun). A fix: skip the wake when every released file is shown in the room by the time the wake turn starts, or let the running turn take the wake.
4. **Open (decision).** In a DM, **Allow for this run** on an own-tool card covers the whole conversation for 30 days: the grant's mission is `conversation:<room>:shared` (`missionOf`, `src/node/device-tools.ts:120`; `knownAnswer`, `src/node/own-tool-asks.ts:57`, `ANSWER_DAYS = 30`). docs/35 says "for this run (the turn's mission)", but the card's ⓘ says "until this run ends" (`apps/node-web/components/chat/computer-card.tsx:63-64`), and the owner sees a new task write there without asking.
5. **Open (gap).** With the phone's browser closed nothing tells the owner a card waits. `noticeAsked` (`src/node/device-tool-decisions.ts:214`) writes a notification that opens the card on the Node site, but the Hub's list drops it at once (`staleNeeds`, `src/notifications/needs.ts:47`: a node's own tool question is answered in the Node chat only), and the website has no notifications or web push. In S3 and S4 the cards waited 3 and 1.5 minutes until the turn parked; the owner finds them only by opening the site.
6. Minor: a write in a new folder through Ensemble's computer tools asked twice (run commands, then change files).
7. Minor: input tokens of resumed DM turns are large: the S3 resume turn 883k, a turn with one `node_show` 145k, a 16 s resume 225k (the DM's session resumes with its whole history and 96 tools).

The browser also logged `POST /api/node/rooms/:id/read` as aborted now and then; the API answers it 204 and no error showed, so it is not counted as a problem.
